# Quick Task 260614-2rn: Add DOM `code`/`key` to synthetic global-keybind events

## Goal

Make global (window-unfocused) keybinds fire for **non-printable** keys — PageUp, PageDown,
Insert, Delete, arrows, F-keys, Home/End, etc. — which currently silently never trigger, while
keeping the already-working printable keys (`]`, `.`, Space) unchanged.

## Root cause (established, not re-investigated)

Discord's keybind matcher is **branched by key class**:
- **printable** keyCodes (letters/digits/OEM punctuation/space) → matched by numeric `keyCode`
- **non-printable** keys (nav/edit/function) → matched by DOM `KeyboardEvent.code`/`key` string

GoofCord's global path dispatches a synthetic `KeyboardEvent` (`keybinds.ts` `keybinds:trigger`)
that carries **only** `keyCode` + modifier flags — no `code`, no `key`. So non-printable keys have
nothing for Discord to match on and never fire, whereas printable keys round-trip via the keyCode
branch. Evidence chain: venbind firing is source-confirmed (thomas-quant/venbind `fork-ci`:
`structs.rs` tokens + `windows.rs` VK map + `ctrl+pageup` unit test); the bind exists in Discord's
store (recorded from a real PageUp), proving Discord *can* represent the key — the only missing
ingredient in our synthetic event is the `code` a real event carries.

Scope note: the **focused** path is a separate delivery/interception issue (`venbind.ts:38`
early-returns on focus) and is intentionally **not** addressed here. Global is the win.

## Tasks

### Task 1 — Add a keyCode → DOM-code map + helper
- **files:** `src/windows/main/preload/keybindShortcut.ts`
- **action:** Add `NAMED_KEYCODE_DOMCODE: Record<number, string>` (non-printable named keys only —
  exclude Space 32, numpad 96-111, printable/OEM) and export
  `keyCodeToDomCode = (keyCode) => NAMED_KEYCODE_DOMCODE[keyCode]`. For every key in the map the DOM
  `key` equals the DOM `code`, so one map serves both. Comment explains *why* (Discord's two-branch
  matcher), mirroring the existing `NAMED_KEYCODE_TOKENS` comment style.
- **verify:** `bun test` (keybindShortcut.test.ts), `bun run check`
- **done:** map + exported helper present; printable keyCodes return `undefined`.

### Task 2 — Thread `code`/`key` onto the synthetic event
- **files:** `src/windows/main/preload/keybinds.ts`
- **action:** Import `keyCodeToDomCode`; extend the `Keybind.eventSettings` type with optional
  `code?`/`key?`; in `getActiveKeybinds`, compute `domCode = keyCodeToDomCode(mainKeyCode)` and
  conditionally spread `{ code: domCode, key: domCode }` into `eventSettings` so printable keys stay
  byte-for-byte unchanged. The `new KeyboardEvent(..., keybind.eventSettings)` dispatch site needs
  no change.
- **verify:** `bun run check`
- **done:** non-printable binds carry `code`/`key`; printable binds emit identical eventSettings.

### Task 3 — Unit test the helper
- **files:** `src/windows/main/preload/keybindShortcut.test.ts`
- **action:** Add a `keyCodeToDomCode` describe block: nav/edit/function keys resolve to their DOM
  code; printable/excluded keys (Space, `]`, `.`, `A`, numpad0) return `undefined`.
- **verify:** `bun test` green (existing 8 + new).
- **done:** new tests pass; no regression.
