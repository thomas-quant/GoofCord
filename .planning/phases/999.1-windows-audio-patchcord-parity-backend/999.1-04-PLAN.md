<objective>
Wire feature 2 (endpoint/source selector) end to end. Plan 03 gave the addon endpoint enumeration + loopback; Plan 02 added `captureSource`/`endpointId` to the config and stubbed the endpoint branch to fail-closed. This plan lights the branch up: enumerate endpoints into the picker, add the selector dropdown, dispatch `system`+`endpoint` to the real endpoint capture, and keep the fail-closed contract.

Purpose: The VAC/Sonar power-user fix — let the user select their clean stream bus (e.g. `SteelSeries Sonar - Stream`) so GoofCord captures echo-free, native-quality audio with no driver and no AEC (the OBS model). Normal users keep zero-config EXCLUDE-self.

Output: A Windows build where system mode offers a capture-source dropdown; picking a render endpoint routes its loopback mix to the viewer; "Default" uses the console default; explicit-endpoint failure yields silence, never a broad fallback.

## Artifacts this phase produces (this plan's contribution)
- `tryStartWasapiLoopback` endpoint dispatch: `mode:"system"` + `captureSource:"endpoint"` → `startRenderEndpoint(endpointId)` (or `startDefaultRenderEndpoint()` when `endpointId === "default"`), mapping failure to `failed-no-fallback`.
- `WasapiAddon` typings for `startRenderEndpoint`, `startDefaultRenderEndpoint`, `listRenderEndpoints`; `RenderEndpointInfo` TS shape `{ id, name, isDefault }`.
- `ScreensharePayload.renderEndpoints: RenderEndpointInfo[]` populated in `fetchScreenshareData` (win32).
- Endpoint selector dropdown in preload.mts: `#endpoint-select` (a `<select>` of "Default" + `renderEndpoints`) inside a `#endpoint-selector-container`, shown for `mode:"system"`; `getFormSettings` reads it into `captureSource`/`endpointId`.

## Assumptions & Deferred (surfaced, not dropped)
- BOX OPEN QUESTION carried from Plan 03: if `SteelSeries Sonar - Stream` turns out to be an eCapture/input device rather than an eRender endpoint, the render-endpoint dropdown will NOT list it. Verify on-box; if so, document a follow-up (a capture-device path) in the SUMMARY — do NOT silently omit. The selector must at least handle every eRender endpoint correctly now.
- Default-render-device-change restart (`IMMNotificationClient`) is DEFERRED — the endpoint is resolved once at share start.
- No new IPC channel: endpoints ride the existing `refreshScreenshareSources` payload; `audioConfig` (with `endpointId`) rides the existing `selectScreenshareSource`. If any `<IPCHandle>`/`<IPCOn>` is added, re-run `bun run build --onlyGenerators`; never hand-edit `gen.ts`/`types.ts`.
- `endpoint-self-cancel`/AEC is DEAD — the dropdown offers only "Default" + real render endpoints; no self-cancel option.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer selector → main IPC | `endpointId` (an arbitrary string) + `captureSource` cross from the sandboxed preload to the native endpoint activation. |
| render endpoint → viewer | The selected endpoint's full mix is streamed to a remote viewer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-999.1-10 | Information Disclosure | endpoint mode fallback | high | mitigate | Explicit-endpoint activation failure → `failed-no-fallback` → `result.audio` UNSET; never Chromium `"loopback"` (which would broadly capture the whole default endpoint the user did not select). Fail-closed is an acceptance criterion. |
| T-999.1-11 | Tampering | endpointId string from renderer | medium | mitigate | `endpointId` is chosen from the enumerated dropdown; the addon resolves it via `GetDevice` and returns `false` (→ fail-closed) on any unresolved/invalid id — an arbitrary/forged id captures nothing, not a different user's audio. |
| T-999.1-12 | Denial of Service | concurrent native + Chromium loopback | high | mitigate | Endpoint capture is single-source through the one `SESSION`; if any native capture starts, `result.audio` stays unset — preserves the CoreMessaging-crash-avoidance invariant. |
</threat_model>
