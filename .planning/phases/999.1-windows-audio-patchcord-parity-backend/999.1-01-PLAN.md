<objective>
Grow the clean-room WASAPI addon with the two Rust primitives that per-app INCLUDE needs: a single-app INCLUDE capture export and an audio-session app enumerator. This is the Rust backend for feature 1 (per-app INCLUDE / the patchcord-parity headline). No TypeScript, no UI — that integration lands in Plan 02 once this addon builds in CI.

Purpose: Today the addon only knows EXCLUDE-of-own-tree (the shipped #211 echo fix). App-exclusive share needs the mirror-image mode (INCLUDE the chosen app) plus a way to enumerate which apps are emitting audio so the picker can list them.

Output: `startIncludeProcessTree`, `listAudioApps` (+ `AudioAppInfo`) exported from BOTH byte-identical Rust mirrors; `start`/`stop`/`run_capture_loop` reused verbatim; a prebuilt `.node` produced by the `thomas-quant/wasapi-loopback` Windows CI.

## Artifacts this phase produces (this plan's contribution)
- Rust napi export `startIncludeProcessTree(targetPid: u32, onChunk) -> bool` (INCLUDE process tree, single PID).
- Rust napi export `listAudioApps() -> Vec<AudioAppInfo>` where `AudioAppInfo = { processId: u32, displayName: String, binary: String }`.
- Internal helper `activate_process_tree(mode, target_pid)` (refactor of `activate_exclude_tree`) so EXCLUDE + INCLUDE share one activation body.
- Legacy `start(exclude_root_pid, onChunk)` retained as the EXCLUDE compat path.

## Assumptions & Deferred (surfaced, not dropped)
- Addon API is `pid`/`pids[]`-shaped from day one, but SHIPS AND VERIFIES N=1 only. Multi-app N-INCLUDE + mixer is DEFERRED (needs the R4 concurrency spike first) — keep the single `SESSION` mutex; do NOT add a mixer.
- `listAudioApps` drops `IsSystemSoundsSession` + the addon's OWN process id here; the Electron Audio Service CHILD pid is dropped on the TS side in Plan 02 (only the main process can resolve it via `app.getAppMetrics()`). This split is intentional.
- Endpoint enumeration / endpoint loopback are OUT of this plan — they land in Plan 03.
- AEC / endpoint-self-cancel / B1 subtraction / window capture are DEAD/PARKED — no config surface, no code.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| target app → addon capture | An arbitrary target PID's audio tree is captured and streamed to a Discord viewer (privacy-sensitive scope). |
| Windows audio subsystem → addon | Session enumeration + async activation cross into COM; failure must not crash the host. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-999.1-01 | Information Disclosure | startIncludeProcessTree scope | medium | mitigate | INCLUDE is engine-side single-tree; the pid comes from the user's explicit picker choice (wired Plan 02). Enumerator drops own PID + system sounds so GoofCord's own audio isn't offered as a capture target. |
| T-999.1-02 | Denial of Service | activation / enumeration FFI | high | mitigate | Every failure collapses to `Unsupported`/`Ok(false)`/`Ok(vec![])`; `ManuallyDrop<PROPVARIANT>` prevents the heap-corruption hard crash; bounded `stop` join preserved. Never panics across FFI. |
| T-999.1-03 | Tampering | dual Rust mirror drift | medium | mitigate | `diff -q` byte-identity is an acceptance criterion on both edits; drift would ship divergent addons from the two build sources. |
</threat_model>
