<objective>
Add the Rust backend for feature 2 (endpoint/source selector): enumerate active render endpoints and loopback-capture a chosen one at the fixed transport format. This is the VAC/Sonar fix primitive — a user points GoofCord at their clean stream bus (e.g. `SteelSeries Sonar - Stream`) and it captures that endpoint's mix, echo-free, no driver, no AEC. No TypeScript/UI here — that lands in Plan 04.

Purpose: The addon today has only the `ActivateAudioInterfaceAsync` process-loopback magic-device path. Endpoint loopback is a different client-acquisition (`IMMDevice`→`Activate(IAudioClient)`), but everything downstream (Initialize flags, capture loop, start/stop) is shared. This plan adds that acquisition + endpoint enumeration.

Output: `listRenderEndpoints`, `startRenderEndpoint`, `startDefaultRenderEndpoint` (+ `RenderEndpointInfo`) in BOTH byte-identical mirrors; a shared `initialize_loopback_client` helper; a prebuilt `.node` (with INCLUDE + endpoint) from the wasapi-loopback Windows CI.

## Artifacts this phase produces (this plan's contribution)
- Rust napi export `listRenderEndpoints() -> Vec<RenderEndpointInfo>` where `RenderEndpointInfo = { id: String, name: String, isDefault: bool }`.
- Rust napi export `startRenderEndpoint(deviceId: String, onChunk) -> bool`.
- Rust napi export `startDefaultRenderEndpoint(onChunk) -> bool`.
- Internal `activate_render_endpoint_loopback(device_id: Option<&str>) -> ActivationResult` and a shared `initialize_loopback_client(audio_client)` helper (the Initialize/stream-flags block extracted so process + endpoint paths stay format-identical).

## Assumptions & Deferred (surfaced, not dropped)
- Only render (`eRender`) endpoints are enumerated/loopback-captured. BOX OPEN QUESTION (from CONTEXT/IMPL-HANDOFF): whether `SteelSeries Sonar - Stream` is exposed as an eRender endpoint (covered here via loopback) OR an eCapture/input device (would need direct capture, NOT endpoint loopback). This plan covers the render-endpoint case; if the box test finds Sonar's Stream bus is a capture device, that is a documented follow-up (surface it in the SUMMARY) — do NOT silently drop it.
- `endpoint-self-cancel` / dual-capture AEC is DEAD — do NOT add any self-cancel activation variant, `CaptureTarget::*SelfCancel`, ring-buffer canceller, or NLMS, despite ENDPOINT-LOOPBACK-DESIGN.md §5 describing one. CONTEXT.md supersedes it: the only two `captureSource` values are `process-exclude` and `endpoint`.
- Default-render-device change restart (`IMMNotificationClient`) is DEFERRED — resolve the default once at share start.
- Single `SESSION` stays one-client — endpoint capture is a single source; NO concurrency with a process capture in the same session.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| render endpoint → addon capture | Loopback captures the FULL mix of the selected endpoint (everything rendered there) and streams it to a viewer. |
| Windows audio subsystem → addon | Endpoint enumeration + IMMDevice activation cross into COM; failure must fail-closed without crashing. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-999.1-07 | Information Disclosure | endpoint loopback scope | medium | mitigate | Endpoint loopback captures ONLY the chosen endpoint's mix; the user selects it explicitly (wired Plan 04). It is the deliberate mechanism for pointing at a clean bus. Fail-closed on activation failure (no broad fallback) is enforced in Plan 04. |
| T-999.1-08 | Denial of Service | IMMDevice activation / enumeration | high | mitigate | Every failure → `Unsupported`/`Ok(false)`/`Ok(vec![])`; never panics across FFI; single `SESSION` + bounded `stop` join preserved; endpoint never co-runs with a process capture in one session. |
| T-999.1-09 | Tampering | dual mirror drift + format divergence | medium | mitigate | `diff -q` byte-identity + a positive assertion that endpoint init routes through `initialize_loopback_client` (fixed format), so no divergent mix-format path can ship. |
</threat_model>
