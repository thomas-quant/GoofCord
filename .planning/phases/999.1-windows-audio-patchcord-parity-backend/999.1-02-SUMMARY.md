## Accomplishments
- **Widened `AudioConfig`** (`preload.mts`) with `captureSource: "process-exclude" | "endpoint"` + `endpointId: "default" | string` — exactly two `captureSource` values (no dead self-cancel variant). Extended the `screensharePreviousSettings` default in `settingsSchema.ts` to match (schema is generic over the imported `ScreenshareSettings`, so a mismatch fails `bun run check`). Normalized older saved configs on load (`s.audioConfig.captureSource ??= "process-exclude"`, `endpointId ??= "default"`) and completed the `getFormSettings` initializer.
- **Config-dispatching wrapper with a fail-closed verdict** (`wasapiLoopback.ts`): `tryStartWasapiLoopback(audioConfig)` now returns `WasapiVerdict = "started" | "unsupported-fallback-ok" | "failed-no-fallback"`. Dispatch: `system`+`process-exclude` → `start(process.pid)` (today's EXCLUDE-self #211 path, byte-unchanged); `app` → `startIncludeProcessTree(pids[0])`; `system`+`endpoint` → fail-closed STUB (Plan 04). App + explicit-endpoint modes map any non-start (unsupported / `!ok` / exception) to `failed-no-fallback`; only system+process-exclude yields `unsupported-fallback-ok`. The `MessageChannelMain` → `port1` → renderer-feeder transport hop is identical for every mode — only the native start call varies.
- **No-DevTools diagnostics:** each share attempt appends one line (`timestamp kind=<exclude-self|include-pid|endpoint-unwired|...> verdict=<...>`) to `userData/wasapi-capture.log` via `fs.appendFile` (best-effort, write errors swallowed).
- **win32 `audioNodes` population** (`screenshare.ts`): `fetchScreenshareData` now fills `audioNodes` from `listWasapiAudioApps()` on win32 (mapped into the `ShareableNode` contract; own Audio Service child PID dropped, mirroring `patchcordList`), added a thin exported accessor rather than importing the raw addon. Added `isWasapiAudio: canRunWasapiCapture()` to the payload.
- **Verdict-branched audio gate** (`screenshare.ts`): win32 branch now `await tryStartWasapiLoopback(audioConfig)` → `"started"` leaves `result.audio` UNSET (preserving the CoreMessaging invariant comment); `"unsupported-fallback-ok"` sets `result.audio = "loopback"` (system+process-exclude only); `"failed-no-fallback"` leaves `result.audio` UNSET and logs the fail-closed decision. The macOS `else` still uses `"loopback"`.
- **Windows advanced UI reachable** (`preload.mts`): added the `isWasapiAudio` payload field + module flag; generalized the advanced-UI, `getFormSettings`, and `refreshData` gates from `isPatchcordMode` to `(isPatchcordMode || isWasapiAudio)` so the audio-mode segmented control + `#audio-apps-list` checklist render on Windows and the checked PIDs are read back into `audioConfig`. Reused the existing `#linux-audio-section` container + localization keys (no HTML restructure). No endpoint dropdown (Plan 04).
