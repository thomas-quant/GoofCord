## Accomplishments
- **`listRenderEndpoints() -> RenderEndpointInfo[]`** — clean-room render-endpoint enumerator from the public MS Core Audio device APIs (mirrors OBS `win-wasapi` enumeration): `CoCreateInstance(MMDeviceEnumerator)` → `EnumAudioEndpoints(eRender, DEVICE_STATE_ACTIVE)` → per `IMMDevice` `GetId()` (id) + `OpenPropertyStore(STGM_READ).GetValue(PKEY_Device_FriendlyName)` (name), with the eConsole default resolved once via `GetDefaultAudioEndpoint(eRender, eConsole)` and tagged onto the matching entry. Runs on a dedicated MTA thread; fail-closed to an empty vec on any COM failure.
- **`startRenderEndpoint(deviceId, on_chunk) -> bool`** and **`startDefaultRenderEndpoint(on_chunk) -> bool`** — endpoint loopback of a chosen (or the eConsole default) render device. The VAC/Sonar fix primitive: point GoofCord at a clean render bus. Both emit the SAME fixed 48k/stereo/f32 480-frame (3840-byte) chunk contract as every other native path.
- **Shared `initialize_loopback_client(&IAudioClient)`** — the single fixed-format `Initialize(AUDCLNT_SHAREMODE_SHARED, LOOPBACK|EVENTCALLBACK|AUTOCONVERTPCM|SRC_DEFAULT_QUALITY, 0, 0, build_wave_format(), None)` block, extracted from the process path and reused by BOTH process and endpoint activation. This is the positive guarantee (threat T-999.1-09) that the endpoint path can never ship a divergent mix-format.
- **`activate_render_endpoint_loopback(device_id)`** — resolves `None`/`"default"` → eConsole default, else `GetDevice(widened UTF-16 id)`; `Activate::<IAudioClient>` on the `IMMDevice`; fixed-format init; any non-success → `Unsupported` (never panics across FFI).
- **Both mirrors byte-identical** (`native/wasapi-loopback/` and `wasapi-loopback-repo/`): `diff -q` on `lib.rs` and `Cargo.toml` both exit 0.

## Decisions Made
- **Shared fixed-format Initialize helper over duplicated stream-flags blocks** — extracting `initialize_loopback_client` and routing both client-acquisition paths through it makes the "endpoint init uses the fixed format, never GetMixFormat" invariant structurally enforced, not just conventionally followed.
- **Direct `IMMDevice::Activate::<IAudioClient>` for endpoint acquisition** (mirrors the existing `IAudioSessionManager2` Activate site) rather than the async magic-device path — endpoint loopback is a plain shared-mode loopback client, no `ActivateAudioInterfaceAsync`.
- **Two thin exports over a shared `start_endpoint_session`** rather than a string-mode argument — unambiguous at the N-API boundary, no capture-skeleton drift.
- **Two new windows-rs feature gates** (`Win32_UI_Shell_PropertiesSystem` for `IPropertyStore`, `Win32_Devices_FunctionDiscovery` for `PKEY_Device_FriendlyName`) — the friendly-name property-store path is the one part of this plan not already covered by Plan 01's feature set; documented in the Cargo.toml comment block for the "gates covered by reading the files" acceptance criterion.
