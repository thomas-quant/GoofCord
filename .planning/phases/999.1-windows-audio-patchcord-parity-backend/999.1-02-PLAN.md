<objective>
Wire feature 1 (per-app INCLUDE) end to end on Windows and land the shared widened AudioConfig model. Today the win32 path calls `tryStartWasapiLoopback()` argless (always EXCLUDE-self) and `fetchScreenshareData` hardcodes `audioNodes = []`, so `audioConfig.mode`/`pids` are thrown away and the app checklist never appears. This plan makes Windows honor `mode:"app"` via the Plan 01 addon, adds the `captureSource`/`endpointId` config fields (consumed fully in Plan 04), and enforces fail-closed.

Purpose: Deliver the patchcord-parity headline — "same API as patchcord, include the app you pick" — and establish the config plumbing + verdict contract that the endpoint selector (Plan 04) reuses.

Output: A Windows build where app-audio mode captures the selected app's tree; the default system path is byte-behavior-identical to #211; failures produce silence, never a broad Chromium fallback; capture diagnostics land in a userData log.

## Artifacts this phase produces (this plan's contribution)
- `AudioConfig` widened to `{ mode; pids; captureSource: "process-exclude"|"endpoint"; endpointId: "default"|string }` (preload.mts; propagates to the `settingsSchema.ts` generic).
- `screensharePreviousSettings` default extended to `{ ...; audioConfig: { mode:"none", pids:[], captureSource:"process-exclude", endpointId:"default" } }`.
- Verdict type `WasapiVerdict = "started" | "unsupported-fallback-ok" | "failed-no-fallback"` and `tryStartWasapiLoopback(audioConfig): Promise<WasapiVerdict>`.
- `WasapiAddon` typings extended with `startIncludeProcessTree(pid, onChunk)` + `listAudioApps()`.
- `ScreensharePayload` gains a `isWasapiAudio: boolean` flag (win32 advanced-UI signal). Endpoint list is added in Plan 04.
- No new IPC channel: `selectScreenshareSource` already carries `audioConfig`; `refreshScreenshareSources` already returns the payload. (If any `<IPCHandle>`/`<IPCOn>` is added, `bun run build --onlyGenerators` MUST be re-run and `gen.ts`/`types.ts` never hand-edited — none is expected.)

## Assumptions & Deferred (surfaced, not dropped)
- N=1 INCLUDE only. `pids` stays array-shaped for later multi-app, but the wrapper dispatches `startIncludeProcessTree(pids[0])`; multi-app + mixer DEFERRED.
- `captureSource:"endpoint"` dispatch + the endpoint selector dropdown are OUT of this plan (Plan 04). This plan adds the fields + normalizes them so old configs are forward-compatible, but the endpoint branch is not yet wired to a running endpoint capture.
- `renderEndpoints` is NOT added to the payload here — Plan 04 adds it.
- The renderer `audioNodes` contract stays `{ processId, displayName, binary }` (ShareableNode-shaped) — do NOT widen it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer picker → main IPC | `audioConfig` (mode, pids) crosses from the sandboxed preload into the main-process capture dispatch. |
| main capture → Discord viewer | Selected app audio (or system mix) is streamed to a remote viewer — a privacy-sensitive egress. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-999.1-04 | Information Disclosure | audio gate fallback | high | mitigate | App mode maps activation failure to `failed-no-fallback` → `result.audio` stays UNSET; NEVER Chromium `"loopback"` (which would silently capture EVERYTHING the user did not ask to share). Fail-closed is an acceptance criterion. |
| T-999.1-05 | Denial of Service | concurrent WASAPI + Chromium loopback | high | mitigate | Preserve the invariant: if any native capture starts, `result.audio` stays unset (the shipped `screenshare.ts` comment) — avoids the CoreMessaging heap-corruption hard crash. |
| T-999.1-06 | Tampering | audioConfig.pids from renderer | low | accept | `pids` is a user-chosen PID from the enumerated checklist; INCLUDE of a wrong PID captures nothing harmful (engine-side scope). Rationale: no privilege boundary crossed beyond the user's own picker choice. |
</threat_model>
