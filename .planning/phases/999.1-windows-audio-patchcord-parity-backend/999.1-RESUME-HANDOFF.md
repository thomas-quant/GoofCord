## Key constraints / gotchas (don't relearn these the hard way)

- **CI-only build.** Never `cargo build/check/clippy` or `bun run build` locally — the addon compiles ONLY in `thomas-quant/wasapi-loopback` CI ("Build prebuilt" = `build.yml`, `workflow_dispatch`, commits the `.node` back to the dispatched ref). GoofCord `testBuild.yml` pulls that **prebuilt** `.node` via `bun install` — it does NOT compile Rust. So: **addon CI first → repoint GoofCord → GoofCord CI.** Allowed static checks: `bun run check`, `bun run lint`, `diff -q`, `grep`.
- **Two byte-identical Rust mirrors:** `native/wasapi-loopback/src/lib.rs` ≡ `wasapi-loopback-repo/src/lib.rs` (+ both `Cargo.toml`). Every Rust edit goes in BOTH; `diff -q` must stay clean. (`wasapi-loopback-repo/` is a plain in-repo copy, not a nested git repo — it's the source you publish to the addon repo.)
- **Fail-closed is a hard invariant:** app-mode + explicit-endpoint activation failure → `failed-no-fallback` → `result.audio` UNSET, NEVER Chromium `"loopback"` (privacy inversion + CoreMessaging crash). Never run native capture concurrently with Chromium loopback.
- **Fixed format:** every native path emits 48k/stereo/f32/3840-byte via the shared helpers (`build_wave_format` / `initialize_loopback_client` + `AUTOCONVERTPCM`). Process-loopback `GetMixFormat` returns `E_NOTIMPL` — never use it.
- **No `bun run fmt`** (reformats 90+ files). Hand-match style.
- **`gh` defaults to upstream** — fork ops need explicit `--repo thomas-quant/...`. CI + branch pushes are user-authorized for the forks (they said "just run ci"); upstream is NOT.
- **No DevTools on the box** — route diagnostics to `wasapi-capture.log` (already wired: logs `include-pid` / `exclude-self` / `endpoint-default` / `endpoint:<id>` / `app-no-pid` + verdict).
- **Dead lineage — keep OUT:** no AEC / self-cancel / NLMS / subtraction. `captureSource` has exactly two values (`process-exclude` | `endpoint`).
