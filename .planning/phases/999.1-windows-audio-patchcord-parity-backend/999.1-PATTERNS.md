### `native/wasapi-loopback/src/lib.rs` (Rust napi addon, streaming) + mirror `wasapi-loopback-repo/src/lib.rs`

**Vendored, in-repo.** Both copies are 569 lines and must stay byte-identical (edit both). Repo: `github:thomas-quant/wasapi-loopback`. New INCLUDE + endpoint + enumerator exports mirror the existing EXCLUDE machinery verbatim.

**Analog 1 — activation (the pattern the new `startIncludeProcessTree` copies):** `activate_exclude_tree`, lines **217-325**.

The ONLY functional change for INCLUDE is the mode constant + doc. Lines **224-233** build the params:
```rust

```
→ INCLUDE variant swaps the constant to `PROCESS_LOOPBACK_MODE_INCLUDE_TARGET_PROCESS_TREE` (import it alongside the existing EXCLUDE constant at line **46**) and `TargetProcessId: include_pid`. Everything else (steps 3-7: the `ManuallyDrop<PROPVARIANT>` VT_BLOB guard lines **244-252**, the `CompletionHandler`/`CreateEventW` async wait lines **254-296**, the `Initialize` with `AUTOCONVERTPCM | SRC_DEFAULT_QUALITY` lines **302-322**) is copied unchanged. **Consider refactoring `activate_exclude_tree` to take a `mode` param** rather than duplicating 100 lines — keeps EXCLUDE + INCLUDE + endpoint activation DRY.

**Endpoint activation** (`startRenderEndpoint`/`startDefaultRenderEndpoint`) has NO in-repo activation analog for the `IMMDevice`→`Activate(IAudioClient)` path (the existing addon only uses the `ActivateAudioInterfaceAsync` magic-device path). BUT the `Initialize` stream-flags block (lines **305-322**) transfers verbatim — same fixed 48k/stereo/f32 `build_wave_format()` + `LOOPBACK | EVENTCALLBACK | AUTOCONVERTPCM | SRC_DEFAULT_QUALITY`. The enumerator exports (`listAudioApps` via `IAudioSessionManager2`, `listRenderEndpoints` via `EnumAudioEndpoints`) have **no in-repo analog** — these are net-new COM-interface usages (see "No Analog" below). windows-rs feature gates must be added.

**Analog 2 — capture loop (reused verbatim, do NOT rebuild):** `run_capture_loop`, lines **362+**. INCLUDE and endpoint paths feed the SAME loop; the emitted chunk format is identical (3840-byte f32). No change.

**Analog 3 — napi export + threaded activation + session lifecycle:** `start`, lines **460-527**; `stop`, lines **532-569**.
```rust
#[napi]
pub fn start(exclude_root_pid: u32, on_chunk: ChunkTsfn) -> napi::Result<bool> {
    let mut guard = SESSION.lock().unwrap_or_else(|p| p.into_inner());
    if guard.is_some() { return Ok(true); }              // idempotent
    let stop_event = /* CreateEventW manual-reset ... */;
    let (tx, rx): (Sender<bool>, _) = channel();          // verdict channel
    let join = std::thread::spawn(move || {
        let com = unsafe { CoInitializeEx(None, COINIT_MULTITHREADED) };  // MTA
        let activation = unsafe { activate_exclude_tree(exclude_root_pid) };
        match activation {
            ActivationResult::Activated(client) => { let _ = tx.send(true);
                unsafe { run_capture_loop(client, on_chunk, stop_handle.0) }; }
            ActivationResult::Unsupported => { let _ = tx.send(false); }
        }
        if com_ok { unsafe { CoUninitialize() }; }
    });
    let supported = rx.recv().unwrap_or(false);           // real support verdict
    // ... on !supported: SetEvent + join + CloseHandle, return Ok(false)
    *guard = Some(CaptureSession { stop_event, join: Some(join) });
    Ok(true)
}
```
→ Each new `#[napi] pub fn startIncludeProcessTree(pid, on_chunk)` / `startRenderEndpoint(device_id, on_chunk)` copies this exact skeleton: single global `SESSION` mutex (line **351**, one-client `SESSION` is fine — multi-INCLUDE deferred), on-capture-thread activation, `channel()` verdict back to JS, `Ok(false)` on any failure (never throws → JS fails closed). Keep `start` as the compat EXCLUDE path. `stop` (lines **532-569**, idempotent `guard.take()` + `SetEvent` + bounded `is_finished()` join) is shared unchanged — all capture kinds stop through it.

**Invariants to preserve (from lines 237-252, 292-296, 460-527):** `ManuallyDrop<PROPVARIANT>` (never `PropVariantClear` a stack blob); any non-`S_OK` → `Unsupported`/`Ok(false)` (dynamic OS floor, no build gate); MTA `CoInitializeEx` on the capture thread; idempotent `stop`.

### `src/modules/native/wasapiLoopback.ts` (TS main-process wrapper, request-response + transport)

**Analog:** its own `tryStartWasapiLoopback` (lines **102-158**) + `patchcord.ts` for the config-branch API shape.

**Addon typing** (lines **38-43**) — extend with the new exports:
```ts
interface WasapiAddon {
	start(excludeRootPid: number, onChunk: (err: unknown, chunk: Buffer) => void): boolean;
	stop(): void;
}
```
→ Add `startIncludeProcessTree(pid, onChunk)`, `startRenderEndpoint(deviceId, onChunk)`, `startDefaultRenderEndpoint(onChunk)`, `listAudioApps()`, `listRenderEndpoints()`. Update the load-guard export check at lines **62-64** if new exports become mandatory (keep the graceful `typeof … !== "function"` null-on-failure pattern).

**Signature change — the core edit** (lines **102-158**). Current argless header:
```ts
export async function tryStartWasapiLoopback(): Promise<boolean> {
	if (process.platform !== "win32" || process.argv.includes("--no-wasapi")) return false;
	const wasapi = obtainWasapiLoopback();
	if (!wasapi) return false;
	// ... rootPid = process.pid; MessageChannelMain hop; wasapi.start(rootPid, onChunk) ...
```
→ becomes `tryStartWasapiLoopback(audioConfig)` and dispatches on the config:
- `system` + `process-exclude` → `wasapi.start(process.pid, onChunk)` (today's path, lines **112-130**).
- `system` + `endpoint` → `startRenderEndpoint(endpointId)` (or `startDefaultRenderEndpoint()` when `endpointId === "default"`).
- `app` → `startIncludeProcessTree(pids[0])`.

The **MessageChannelMain transport hop is identical for all three** (lines **117-143**) — reuse verbatim: create channel, keep `port1`, `mainWindow.webContents.postMessage("wasapi:pcm-port", null, [channel.port2])`, forward chunks via `toArrayBuffer` (lines **88-92**) down `port1`. Only the `wasapi.start(...)` call at line **130** varies by mode.

**Verdict / fail-closed** (lines **145-157**). Today: `if (!ok) { await stopWasapiLoopback(); return false; }` → falls through to `"loopback"`. New: return a **richer verdict** (`started` / `unsupported-fallback-ok` / `failed-no-fallback`). App mode + explicit-endpoint mode must map failure to `failed-no-fallback` so the caller leaves `result.audio` UNSET (no Chromium fallback). Only `system`+`process-exclude` may return `unsupported-fallback-ok`.

**Diagnostics logging** — mirror the existing `console.log(LOG_PREFIX, ...)` at line **152** but also route capture-kind to the userData log file (no DevTools on the box; see MEMORY "windows-verification-no-devtools").

**Teardown reuse:** `stopWasapiLoopback` (lines **164-186**) and the `before-quit` `Promise.race([stop, timeout])` (lines **189-196**) are mode-agnostic — no change.

**Cross-file API-shape reference — `patchcord.ts`:** the Linux side already models mode-split entry points: `patchcordStartSystem(excludePids)` (lines **117-121**) vs `patchcordStartApp(targetPids)` (lines **127-130**), both returning a nullable result, plus idempotent `stopPatchcord` (lines **151-166**) and the `before-quit` race (lines **168-184**). Mirror this functional parity (not the plumbing).

## Shared Patterns

### Fail-closed audio gate
**Source:** `screenshare.ts:94-114` (the 3-way gate) + `wasapiLoopback.ts:145-157` (verdict).
**Apply to:** `screenshare.ts` gate + `wasapiLoopback.ts` dispatch.
App mode and explicit-endpoint mode never fall back to Chromium `"loopback"` (privacy inversion + CoreMessaging hard-crash). Only `system`+`process-exclude` may fall back.

### Idempotent native lifecycle + bounded before-quit
**Source:** `wasapiLoopback.ts:164-196` and `patchcord.ts:151-184` (both: idempotent `stop*` + `Promise.race([dispose, 1500ms])` on `before-quit`); Rust `stop` at `lib.rs:532-569`.
**Apply to:** all new capture kinds — they share the single `SESSION` mutex and the one `stopWasapiLoopback`/Rust `stop`; no new teardown code.

### MessageChannelMain PCM transport (never per-frame ipcRenderer)
**Source:** `wasapiLoopback.ts:117-143` + `toArrayBuffer` (lines **88-92**).
**Apply to:** all three start modes — identical hop; only the `wasapi.start*(...)` call varies.

### Fixed 48k/stereo/f32 format everywhere
**Source:** Rust `build_wave_format()` + `Initialize` stream-flags `lib.rs:305-322`.
**Apply to:** INCLUDE and endpoint activation both use `AUTOCONVERTPCM | SRC_DEFAULT_QUALITY` at the fixed format — NOT `GetMixFormat`. The TS feeder (`wasapiTransport.ts`) stays format-agnostic and unchanged.
