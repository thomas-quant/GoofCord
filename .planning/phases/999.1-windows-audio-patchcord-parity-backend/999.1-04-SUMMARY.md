## Accomplishments
- **Endpoint dispatch in the wrapper** (`wasapiLoopback.ts`): replaced the Plan 02 fail-closed STUB — `mode:"system"`+`captureSource:"endpoint"` now dispatches to `wasapi.startDefaultRenderEndpoint(onChunk)` when `endpointId === "default"`, else `wasapi.startRenderEndpoint(endpointId, onChunk)`, over the SAME unchanged `MessageChannelMain → port1 → renderer-feeder` hop (only the native start call varies). The addon boolean maps `true → "started"`, `false → "failed-no-fallback"` (endpoint's `closedVerdict` is `failed-no-fallback` because `toleratesFallback` is false unless `captureSource==="process-exclude"`). `system`+`process-exclude` → `unsupported-fallback-ok` and `app` → `failed-no-fallback` unchanged.
- **Addon typings + accessor** (`wasapiLoopback.ts`): extended `WasapiAddon` with `startRenderEndpoint(deviceId, onChunk): boolean`, `startDefaultRenderEndpoint(onChunk): boolean`, `listRenderEndpoints(): RenderEndpointInfo[]`; added an exported `RenderEndpointInfo { id, name, isDefault }` type (documentation-grade under `@ts-nocheck`) and a fail-closed `listRenderEndpoints()` accessor ([] off-win32 / --no-wasapi / addon-missing / when the `.node` predates the endpoint exports / any throw). The endpoint exports are NOT added to the load guard (graceful null-on-failure preserved).
- **userData diagnostics extended** (`wasapiLoopback.ts`): the per-share capture-kind log now records `endpoint-default` / `endpoint:<id>` as the resolved kind alongside the existing `exclude-self` / `include-pid`.
- **Render endpoints in the payload** (`screenshare.ts`): `fetchScreenshareData` fetches the render-endpoint list on win32 via the wrapper's `listRenderEndpoints()` (synchronous + self-guarded, fail-closed to []) and adds it to the returned payload as `renderEndpoints`. `audioNodes` / `isWasapiAudio` from Plan 02 are untouched. The `selectScreenshareSource` verdict branch needed NO structural change — endpoint mode → `failed-no-fallback` flows through the existing gate leaving `result.audio` UNSET (confirmed by read-through; no new `result.audio = "loopback"` added).
- **Capture-source dropdown UI** (`preload.mts`): added a local `RenderEndpointInfo` type + `renderEndpoints` to `ScreensharePayload`. Built a `<select id="endpoint-select">` inside a `#endpoint-selector-container` (`.setting-group`), populated with a "Default" option (value `"default"`) + one option per `payload.renderEndpoints` entry (value = endpoint `id`, text = friendly `name`, the `isDefault` one tagged), injected into `#linux-audio-section .settings-grid` only on Windows (`isWasapiAudio`) and shown only for `mode:"system"` (wired into `updateAppListVisibility` — hidden for app/none). Preselects the stored `s.audioConfig.endpointId`, escaping ids/names via `escapeHtml`.
- **captureSource derivation** (`preload.mts` `getFormSettings`): on the Windows/advanced path, reads `#endpoint-select`'s value and sets `captureSource:"endpoint"` + `endpointId` ONLY when `mode==="system"` and the choice is a non-`"default"` endpoint id; otherwise the initialized `captureSource:"process-exclude"` / `endpointId:"default"` defaults stand — so "Default", app mode, and none mode never flip a normal user into endpoint mode.

## Threat Surface
All three mitigations from the plan's `<threat_model>` are implemented (correctness requirements, not features):
- **T-999.1-10 (Information Disclosure — endpoint mode fallback):** explicit-endpoint activation failure → `false` → `closedVerdict = "failed-no-fallback"` → `result.audio` stays UNSET → never Chromium `"loopback"` (which would broadly capture the whole default endpoint the user did not select). Verified structurally: `result.audio = "loopback"` appears only in the `unsupported-fallback-ok` arm + the macOS `else`, never for endpoint mode.
- **T-999.1-11 (Tampering — `endpointId` from renderer):** `endpointId` is chosen from the enumerated dropdown; the Rust addon resolves it via `GetDevice` and returns `false` on any unresolved/invalid/forged id → fail-closed (captures nothing, never a different device). The wrapper maps that `false` to `failed-no-fallback`.
- **T-999.1-12 (DoS — concurrent native + Chromium loopback):** endpoint capture is single-source through the one addon `SESSION`; if any native capture starts (`"started"`), `result.audio` stays unset — the CoreMessaging-crash-avoidance invariant is preserved.
No NEW security-relevant surface: no new IPC channel (endpoints ride the existing `refreshScreenshareSources` payload; `audioConfig` with `endpointId` rides the existing `selectScreenshareSource`), no new network egress, no schema change at a trust boundary.
