## Accomplishments
- **`startIncludeProcessTree(target_pid, on_chunk) -> bool`** — single-app INCLUDE process-tree loopback (Discord-style app-exclusive share). Reuses the exact clean-room machinery as EXCLUDE: single `SESSION` mutex idempotency, MTA `CoInitializeEx` on the capture thread, on-thread activation + `channel()` verdict, `run_capture_loop` at the fixed 48k/stereo/f32 3840-byte chunk contract, `Ok(false)` fail-closed on any non-support. The ONLY divergence from `start` is the `PROCESS_LOOPBACK_MODE_INCLUDE_TARGET_PROCESS_TREE` constant.
- **`listAudioApps() -> AudioAppInfo[]`** — clean-room audio-session enumerator from the public MS Core Audio APIs: `CoCreateInstance(MMDeviceEnumerator)` → `EnumAudioEndpoints(eRender, DEVICE_STATE_ACTIVE)` → per endpoint `IMMDevice::Activate::<IAudioSessionManager2>()` → `GetSessionEnumerator()` → `IAudioSessionControl2::GetProcessId()`. Dedupes by PID; drops `IsSystemSoundsSession` sessions and `GetCurrentProcessId()` (own PID); names via session `GetDisplayName()` with a `QueryFullProcessImageNameW` basename fallback. Runs on a dedicated MTA thread; fail-closed to an empty vec on any COM failure.
- **DRY activation:** `activate_exclude_tree` refactored into `activate_process_tree(mode, target_pid)` with a thin EXCLUDE wrapper — the legacy `start` (shipped #211 echo fix) call site and runtime behavior are byte-for-byte unchanged.
- **Both mirrors byte-identical** (`native/wasapi-loopback/` and `wasapi-loopback-repo/`): `diff -q` on `lib.rs` and `Cargo.toml` both exit 0.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Reject unexpanded resource-ref display names in the name fallback**
- **Found during:** Task 2 (listAudioApps display-name logic)
- **Issue:** The plan says "name = session GetDisplayName() if non-empty, else the basename". Windows frequently returns an *unexpanded* indirect resource string (e.g. `@%SystemRoot%\System32\AudioSrv.Dll,-202`) from `GetDisplayName`, which is technically non-empty but renders as gibberish in the picker.
- **Fix:** Treat a display name that is empty OR starts with `@` as "no friendly name" and fall back to the `QueryFullProcessImageNameW` basename. Small, in-scope robustness for the picker contract.
- **Files modified:** both `src/lib.rs` mirrors (`session_display_name`).
- **Verification:** static only (CI-only-build rule); logic reviewed against the documented `GetDisplayName` behavior.
- **Committed in:** `634b77d` (Task 2 commit).

**2. [Rule 2 - Missing Critical] Drop the PID 0 "no single process" sentinel**
- **Found during:** Task 2 (session → PID mapping)
- **Issue:** A cross-process/grouped session can report process id 0 (`AUDCLNT_S_NO_SINGLE_PROCESS`-adjacent); surfacing PID 0 as a capture target is meaningless and would make an un-INCLUDE-able picker entry.
- **Fix:** Skip `pid == 0` alongside the own-PID and system-sounds drops.
- **Files modified:** both `src/lib.rs` mirrors (`collect_audio_apps`).
- **Verification:** static only.
- **Committed in:** `634b77d` (Task 2 commit).
