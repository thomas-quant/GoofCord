<objective>
Slice 2, part 1 (build the real capture). Build the clean-room native WASAPI process-tree EXCLUDE loopback `.node` addon — the actual echo-fix mechanism. It captures the full default-endpoint mix EXCEPT the process tree rooted at GoofCord's own Electron PID, so the call audio GoofCord itself plays is excluded and no longer echoes back to viewers (#46 / ECHO-01). The addon is the only genuinely novel code in this phase: a ~few-hundred-line mechanical re-expression of the public Microsoft `ApplicationLoopback` MIT sample via the `windows` crate + napi-rs, never from Discord code (ECHO-04).

This plan ONLY proceeds after Plan 01's transport GO — there is no point building native capture until the path it feeds is proven. The addon emits the exact 48k/stereo/f32 contract Plan 01's MSTG feeder already consumes, and pushes 480-frame chunks over a napi `ThreadsafeFunction` — which Plan 03 wires to the same `MessagePortMain` transport, swapping the synthetic tone for real capture.

Purpose: Produce the prebuilt `wasapi-loopback-win32-x64.node` that Plan 03 packages and integrates. The crate lives in-repo (`native/wasapi-loopback/`) for Phase 4 and is extracted to its own published repo in Phase 5 (CONTEXT Open Q1 / RESEARCH Open Q1 resolution). GoofCord's Bun build does NOT compile Rust — the `.node` is consumed prebuilt (CLAUDE.md "no new build tooling").
Output: A buildable Rust crate at `native/wasapi-loopback/` that, on a `windows-latest` runner via `napi build --release --target x86_64-pc-windows-msvc`, produces `wasapi-loopback-win32-x64.node` exporting `start(excludeRootPid, onChunk)` and `stop()`.
